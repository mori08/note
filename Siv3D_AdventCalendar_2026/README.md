# Siv3D: ゲームをAIと作った
## はじめに
ヒューマンインザループという言葉があるらしい。

> ヒューマン・イン・ザ・ループ（HITL）とは、人間が自動化システムの操作、監督、意思決定に積極的に関与するシステムやプロセスを指します。AIの文脈では、HITLとは、人間がAIのワークフローのいずれかの段階に関与し、正確性、安全性、説明責任、倫理的意思決定を確保することを意味します。

今年はバイブコーディングに挑戦し、AIに何を任せて人間は何をすべきなのかを考えて試す年になった。
個人でのゲーム開発の中でHITLを自分の中でどう解釈して落とし込んだか、この記事にメモしようと思う。

## コーディング・開発サイクル

### Siv3Dとバイブコーディング
感想をいくつか書く。

* GUIエディタが不要なのでバイブコーディングは導入しやすかった
* MSBuildを使ってビルドする
  * VisualStudio経由でのビルドのままだと自動化しづらい
  * build.sh にビルド手順をまとめて、claudeに使わせた
* 思っていたよりちゃんとSiv3Dのライブラリをうまく使ってくれる
  * 当初は描画周りの処理がうまくできるか不安だったが問題なし
  * `s3d::Max` とかはあまり使ってくれない（`std::max` の方を採用しがち）
* ゲームの操作感やビジュアルは人間の手と目でテストしている
  * AIである程度自動化してみたかったが、難しくて断念


### /resolve-issue
開発サイクルの土台になるskill。
指定されたIssueを確認し、以下を CreateTask で登録、対応するスキルを順次呼び出す。
（各スキルについて、💻 がAI, 👤 が私）

* Phase 1: `\plan-issue`
  * 💻 調査・計画をサブエージェントで行い、`tmp/plan-<number>.md` に保存
  * 👤 計画を確認し、フィードバック
  * 💻 フィードバックを受け計画を更新、これを 👤 が承認するまで続ける
* Phase 2: `\implement-issue`
  * 💻 サブエージェントで計画を読ませて実装
  * 💻 サブエージェントでci(clang-format, clang-tidy, build, test)を実行
  * 💻 サブエージェントでコードレビュー
  * 👤 exeを起動して操作しながらテストプレイ
  * ci/review/テストプレイ のいずれかでNGが出たら修正して再チェック
* Phase 3: `\commit-pr`
  * 💻 コミットメッセージを決めて commit
  * 💻 branchやcommitを 👤 に確認させ、OKならば push
  * 💻 Pull Request を作成
* Phase 4: `\address-review`
  * 👤 PRでコードを読み、💻 にフィードバック
  * 💻 内容を修正しコミットやPRを修正、これを 👤 がマージするまで続ける
* Phase 5: `\cleanup`
  * 💻 一時ファイルの削除
  * 💻 ローカルのブランチ整理

基本的には `/implement-issue` 等が実装をやってくれるので、私はコードを1文字も書いていない。

### 人間としてやったこと
やったことは大きく分けると２つ。
「人間側が責任を持つべきこと」と「人間側にしかできないこと」

#### 人間が責任を持つべきこと
人間がIssueを進める順番を決定し、人間も計画や実装には目を通してレビューをする。
人間が責任を持つべき箇所に人間が介入できる開発サイクルを作る。

AIは書いたコードに責任を持たない。
バグがあっても、パフォーマンスが悪くても、設計が悪くて開発後半負債になっても、
責任をとるのは人間側なので、AIに全任せにはしない。

#### 人間にしかできないこと
作りたいゲームを頭の中に描き、それを言語化して、AIに伝える。
実際に遊んでみて、その感想を言語化して、AIに伝える。

「こんなゲームを作りたい」という意思の部分と、
「ここが楽しい/楽しくない」という感情の部分は、
人間が整理・言語化し、issueやレビューという形でAIに与える。

#### 人間にしかできないこと（？）
Claude Codeをターミナル外で活動させるのが難しかったので、テストプレイは全て人間側でやった。
ただ、基本的な（Dキーを押して右に進むような）テストまで人間がやるべきかは疑問。
「人間にしかできないこと」ではないはずなので、AIが動けるような工夫ができたらより良かった。
